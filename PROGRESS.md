## 2026-10-08 — Port from Python to TypeScript with Effect

Behaviour-preserving rewrite of every module under the old `app/` into `src/` (TypeScript on Node.js 24, Effect 4.0.2 with `@effect/platform-node` and `@effect/sql-sqlite-node`), keeping every `bin/` command, request and acknowledgement shape, the SQLite schema and file (journal mode `delete`, no migration), the dashboard pages, API routes, privacy rules and snapshots. The Python sources, `app/Melbourne.tzif` (Intl supplies Melbourne time now) and the unittest files are gone. Files: `src/*.ts`, `src/bin/*.ts`, `bin/*` (now exec `${RITUAL_NODE:-node}`), `tests/*.test.ts` with `tests/helpers/`, `tools/ui-fixture.ts` and `tools/screenshot-page.ts` behind the unchanged Playwright checks, `native/` (the app launches `bin/ritual-server` with the Node binary recorded at build time; `build.sh` takes a third NODE argument), `package.json`/`package-lock.json`/`.node-version`/`tsconfig.json`/`vitest.config.ts`/`.oxlintrc.json`/`.oxfmtrc.json`, and AGENTS.md/HANDOFF.md/README.md for the new stack. Tests: all 113 Python cases ported one to one (`bin/ritual-tests`, 12 files, pass), `bin/ritual-ui-check` 16 cases pass, `npm run check` clean. Before deleting the Python, both CLIs ran the same 46-request sequence on copies of the fixture data: every acknowledgement, read, error and queue result matched after normalising timestamps and paths, both static snapshots and both live pages were byte-identical, and each side restored the other's export with identical `data_sha256`. Not deployed: landing, `npm ci` in the live folder, the native rebuild with the Node 24 path (the installed app still launches the removed Python server, so the service breaks until it is rebuilt and reinstalled per HANDOFF.md) and the restart are the next agent's steps. Known differences: JSON numbers print `50` where Python printed `50.0`; a malformed stdin request reports Node's JSON parse message rather than Python's.
